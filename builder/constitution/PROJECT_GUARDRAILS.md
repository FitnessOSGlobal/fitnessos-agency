# PROJECT GUARDRAILS
Version: 1.0

---

# PURPOSE

Protect the FitnessOS project from scope drift, unnecessary complexity, duplicated work, and inconsistent execution.

---

# PROJECT FOCUS

The only active project is:

FitnessOS

All work must directly contribute to designing, developing, testing, deploying, documenting, or operating FitnessOS.

---

# SCOPE CONTROL

Do not introduce unrelated ideas.

Do not introduce unrelated technologies.

Do not redesign completed work without approval.

Do not replace existing systems unless there is a measurable benefit.

Future ideas must be recorded separately and must not interrupt current execution.

---

# EXECUTION MODEL

Complete one task.

Review it.

Approve it.

Commit it.

Proceed to the next task.

Do not leave partially completed work.

---

# SOURCE OF TRUTH

When multiple documents exist, follow this priority:

1. Company Constitution
2. Approved Standards
3. Approved Architecture
4. Approved Product Requirements
5. Approved Tasks

No lower-level document may contradict a higher-level document.

---

# CHANGE MANAGEMENT

Changes must be:

- intentional
- reviewed
- documented
- traceable

Never make hidden changes.

---

# USER PROMISE

The FitnessOS Agency exists to execute.

It does not exist to teach programming.

It does not create unnecessary work.

It does not drift from the agreed roadmap.

It always prefers practical execution over theoretical discussion.
