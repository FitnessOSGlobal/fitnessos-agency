# ATTENDANCE AGGREGATE MODEL

Version: 1.0.0

Status: Draft

Owner: Database Architecture

---

# Purpose

This document defines the aggregate boundaries for the Attendance Domain.

Each aggregate establishes a transactional consistency boundary, ownership rules, and lifecycle responsibilities.

Attendance aggregates own only attendance-related data and reference external domains through identifiers.

---

# Aggregate Overview

The Attendance Domain contains four primary aggregates:

1. Attendance Session
2. Attendance Event
3. Access Device
4. Gate Event

Each aggregate has a single aggregate root.

---

# Aggregate 1 — Attendance Session

## Aggregate Root

Attendance Session

### Purpose

Represents a complete member visit to a facility.

### Owns

- Check-In Timestamp
- Check-Out Timestamp
- Visit Duration
- Branch Reference
- Member Reference
- Membership Reference
- Session Status

### Business Rules

- A session begins with a successful check-in.
- A session ends with a successful check-out.
- A session cannot have multiple check-ins.
- Check-out cannot occur before check-in.
- Sessions are immutable after completion except for authorized administrative corrections.

---

# Aggregate 2 — Attendance Event

## Aggregate Root

Attendance Event

### Purpose

Records every operational attendance action.

### Owns

- Event Type
- Event Timestamp
- Validation Result
- Device Reference
- Operator Reference
- Session Reference

### Business Rules

- Events are append-only.
- Events are never deleted.
- Every event belongs to exactly one attendance session.
- Events must preserve chronological order.

---

# Aggregate 3 — Access Device

## Aggregate Root

Access Device

### Purpose

Represents physical or digital devices used to validate access.

### Owns

- Device Identifier
- Device Type
- Branch Assignment
- Status
- Firmware Information

### Business Rules

- Devices belong to one branch.
- Devices may process many attendance events.
- Device history must be retained.

---

# Aggregate 4 — Gate Event

## Aggregate Root

Gate Event

### Purpose

Represents low-level access control activity generated by gates, scanners, turnstiles, or biometric systems.

### Owns

- Raw Device Event
- Authentication Result
- Device Timestamp
- Synchronization Status

### Business Rules

- Gate events are immutable.
- Failed authentication attempts are retained.
- Events are retained for auditing and diagnostics.

---

# Aggregate Relationships

Attendance Session

↓

Attendance Event

↓

Gate Event

Access Device

↓

Attendance Event

Attendance Session references:

- Organization
- Branch
- Member
- Membership

These entities remain owned by their respective domains.

---

# Ownership Rules

Attendance owns:

- Sessions
- Events
- Devices
- Gate Events

Attendance references:

- Organizations
- Branches
- Members
- Memberships
- Employees

No Attendance aggregate owns external business entities.

---

# Transaction Boundaries

Each aggregate maintains transactional consistency independently.

Cross-domain consistency is achieved through published events rather than distributed transactions.

---

# Future Aggregates

The model allows future aggregates including:

- Visitor Session
- Parking Session
- Facility Occupancy
- Smart Lock Event
- Wearable Device Event

These can be introduced without modifying existing aggregate boundaries.
