# Purpose

This document defines the logical database model for the Attendance Domain.

It translates business entities into logical database structures while remaining independent of any specific implementation technology.

The logical model establishes entity relationships, ownership, and normalization rules that will later be implemented using PostgreSQL and Drizzle ORM.

---

# Logical Entities

The Attendance Domain consists of four logical entities:

1. Attendance Session
2. Attendance Event
3. Access Device
4. Gate Event

Each entity maps to a single primary table.

---

# Attendance Session

Represents a complete member visit.

Relationships:

- One Organization
- One Branch
- One Member
- One Membership
- Many Attendance Events
- Many Gate Events

---

# Attendance Event

Represents an operational event occurring during a session.

Relationships:

- One Attendance Session
- One Access Device
- One Operator (Platform User)

---

# Access Device

Represents a hardware or software endpoint used for access validation.

Relationships:

- One Branch
- Many Attendance Events

---

# Gate Event

Represents raw access activity generated by entry devices.

Relationships:

- One Attendance Session
- One Access Device

---

# Normalization

The logical model targets Third Normal Form (3NF).

Principles:

- No duplicated business data.
- Foreign keys reference authoritative domains.
- Attendance owns only attendance-specific information.
- Derived values are computed rather than duplicated where practical.

---

# Multi-Tenant Model

Every logical business entity includes:

- organization_id

Tenant isolation is enforced at every level.

---

# Audit Model

Every logical entity contains:

- created_at
- updated_at
- created_by
- updated_by

Event entities additionally contain immutable event timestamps.
