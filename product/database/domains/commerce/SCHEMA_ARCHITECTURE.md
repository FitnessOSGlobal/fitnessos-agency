# COMMERCE DATABASE SCHEMA ARCHITECTURE

Version: 1.0.0

Status: Draft

Owner: Database Architecture

---

# Purpose

This document defines the PostgreSQL schema architecture for the Commerce Domain.

The Commerce schema owns all financial persistence objects while referencing business entities from other domains using foreign keys.

---

# Schema Name

commerce

---

# Schema Ownership

Owns:

- orders
- order_items
- invoices
- invoice_items
- payments
- payment_methods
- refunds
- discounts
- tax_rules
- subscriptions
- receipts

Only the Commerce Domain may modify these tables.

---

# External References

## Platform

- organization_id
- branch_id
- user_id

## Membership

- member_id
- membership_id

## Inventory

- product_id

## CRM

- opportunity_id

Commerce never owns these entities.

# Primary Keys

All tables use UUID primary keys generated by PostgreSQL.

---

# Foreign Keys

Commerce references authoritative entities owned by:

- Platform
- Membership
- Inventory
- CRM

Cross-domain ownership is prohibited.

---

# Audit Strategy

Every table includes:

- created_at
- updated_at
- created_by
- updated_by

Financial transactions also include immutable business timestamps.

---

# Index Strategy

Primary indexes:

- organization_id
- member_id
- invoice_number
- payment_reference
- subscription_status
- order_status
- invoice_status
- payment_status
- created_at

Composite indexes optimize:

- Daily Revenue
- Outstanding Invoices
- Subscription Renewals
- Member Purchase History
- Financial Reconciliation

---

# Multi-Tenant Strategy

Every business table contains:

organization_id

Tenant isolation is mandatory.

Cross-tenant financial access is prohibited except for authorized platform administration.

---

# Retention Strategy

Financial records are retained permanently.

Operational deletion is prohibited.

Historical financial data may be archived but must remain recoverable.

---

# Performance Considerations

The schema is optimized for:

- High-volume POS transactions
- Concurrent payment processing
- Subscription billing
- Financial reporting
- Tax reporting
- AI analytics

---

# Future Expansion

Future tables may include:

- wallet_transactions
- loyalty_accounts
- gift_cards
- installment_plans
- settlement_batches

These additions must preserve existing schema boundaries.
